# RD-A01 / RD-A03 — V406-R | مرجع تراکنشی نقاط بازیابی و Disaster Recovery

- Baseline: main@3815b42859ca6e6d4e32343f58bdb794c7abb02a (V405-R)
- Severity: P1; focused source changes, runtime acceptance pending. No whole-product closure.

## Authority decision and boundary
IndexedDB `workspace-commit-v1` is the canonical record for an explicitly committed workspace recovery point. Record format `roomdesigner-workspace/v1` has version, ID, date, exact managed values, length and noncryptographic FNV checksum. The 13 keys cover active drawing, saved profiles/revisions, types, catalog, SVG drafts, shortcuts, users/current user, workspace/toolbox layout, equipment/connection versions and save generation. Other origin keys and legacy archives/journals are outside projection. A new checkpoint is admitted only when the durable drawing exactly matches the mirror and the expected prior IDB authority is unchanged; old checkpoints are retained as history if distinct.

The existing LocalStorage editor and ordinary asynchronous mirror remain unchanged. This version does not claim cross-store atomicity for ordinary Autosave and does not automatically promote an older checkpoint at startup. The explicit recovery checkpoint is authoritative for the selected restore transaction only.

## Managed workspace Disaster Recovery
- Recovery Center exposes checkpoint, workspace JSON export, optional history-inclusive export, restore current checkpoint or V406 package, and historical entry management.
- Restore validates current schema, geometry via existing Import validator, profiles, shortcut structure, resource references, types/catalog, local SVG sanitization and settings; legacy or unsupported target is rejected instead of silently migrating destructive data. Checksum detects accidental corruption, not authenticity; use only trusted backups.
- Before restore, export the current managed workspace and available IDB evidence and require explicit external retention acknowledgment. Check current durable bytes, editor identity, epoch and stable state. Stage immutable before and target records plus previous mirror/checkpoint under `workspace-restore-intent-v1` in a guarded IDB transaction.
- At startup, before legacy migration or editor writes, compare every managed key against the exact before/target alternatives. A third state blocks recovery; no automatic overwrite. Write and verify a durable local marker before projection, project only allowlisted keys, verify exact results. Finalize canonical checkpoint, mirror+metadata, history and completion receipt in one IDB transaction; clear intent only atomically with finalization. A leftover marker is removed only with a matching completion receipt.
- Quota failure, interruption or unavailable IDB with marker leaves recovery pending, with early error/export/retry and explicit rollback request. Rollback uses the retained before state and prior mirror/checkpoint. No blanket clearing of localStorage or IDB.
- History is separately exportable. Historical records can be selected for restore. Current/previous target data are retained in IDB history on finalization; old/unsupported records may remain only exportable.

## Capacity management
Display estimated LocalStorage UTF-16 bytes, local archive size/count and origin usage/quota where browser reports it; warn at 80% of estimated quota. Bound managed values to 12 million characters, intent to 48 million, full JSON export to 64 million, and aggregate history reads to 32 million. Key-only listing avoids loading all workspace history bodies. These are application limits, not guaranteed browser storage capacity. Existing quota errors fail closed.
Only an explicitly selected workspace historical entry may be removed, after file() returns true (confirmed physical write, not anchor-download request) and a separate user acknowledgment. IDB transaction checks the exact selected content and absence of a pending restore. Never remove current checkpoint, pending intent, unrelated data or legacy migration archive through this action. No automatic pruning.

## Remaining / acceptance
- Ordinary autosave remains legacy-compatible: OPEN-CROSS-STORE is still open for normal editing. Explicit checkpoints are not continuous full-workspace saves.
- Current-schema managed keys only: no blanket full-origin, raw legacy journal, archive history import/repopulation, or automatic older-version migration. History is preserved/exportable; older raw files can use existing drawing restore path.
- Projection is not an atomic cross-store transaction; interruption is handled by durable intent+marker with exact rechecks. Older app versions may not understand the marker. Complete browser loss requires external backup; checksum is not authentication.
- Eight regression scenarios authored (record validation/bounds, optimistic checkpoint, interrupted replay, unexpected third state, quota/rollback, marker/receipt, exact history pruning/bounds, source sequencing). All NOT_RUN under POLICY. No Test/Build/Browser/Device execution. Use isolated browser profiles and test real saved NRD/workspace files, including failure injection, before operational use.
