# RD-A01 / RD-A03 — V404-R | حفاظت تراکنشی آینه و آرشیوهای مشترک بازیابی

- Baseline: main@8176de971f2af4d43b59a09f5459b479fbc61b5a (V403-R)
- Severity: P1; focused source fixes, runtime acceptance pending. Both missions remain partially open.

## Findings and source corrections
- RD404-A03-MIRROR-ARCHIVE-RETENTION: previous fixed mirror archive keys protected only a first state. New IndexedDB keys `pre-migration-v404:N` hold immutable distinct mirror/metadata pairs. A readwrite transaction reads the current pair, checks any expected pair, deduplicates equal pairs and uses add, not put. Only transaction completion reports success. Legacy keys remain readable.
- RD404-A01-MIGRATION-PREFLIGHT: startup mirror protection occurs before legacy equipment migration or pending-journal reconciliation when the database is accessible. Existing local project data requiring migration/recovery with supported but inaccessible IDB blocks startup before those mutations; the error panel exports available raw data and flags failed reads. A second local archive protects changed bytes before connection migration when needed. Recovered legacy mirror is archived before equipment/connection transforms; unclassified differing mirror and orphan metadata are protected before continuing.
- RD404-A03-COMBINED-EXPORT: the migration export includes retained LocalStorage archives, both legacy IDB keys and the new IDB archives. It can appear for mirror-only archives and discloses incomplete reads before exporting. Startup discovery uses a key cursor and reads the legacy archive only if needed; full bodies are loaded on export.

## Authority decision and remaining work
The main local document remains the existing authority when valid. Do not infer recency from timestamps or generation sidecars alone; preserve both candidates if there is ambiguity. The new IDB archive transaction is atomic within IDB, not across browser stores. A future durable authority protocol needs a canonical document/revision envelope, a persisted commit record in the authoritative store, deterministic reconciliation on every crash boundary, legacy compatibility, and an independently tested rollback path. No authority migration has been applied in V404-R.

## Risks / acceptance
- OPEN-CROSS-STORE and complete controlled archive restore remain OPEN. Retained archives consume quota; no automatic deletion or pruning. Export can require significant memory and may be incomplete if either store is inaccessible.
- Existing local-only behavior remains for unavailable storage where no pre-existing local project is undergoing a supported-but-inaccessible IDB migration. Legacy startup/journal operations are not made atomic across the stores.
- Five new regression scenarios authored (three fake-IDB contracts, two source contracts); existing archive export contract updated. All NOT_RUN under POLICY. No test, build, browser or device execution. Acceptance should cover distinct pairs, unchanged retries, stale expected pair, DB failure, migration ordering, corrupt/orphan mirror, mirror-only export and partial read warning on isolated data.
