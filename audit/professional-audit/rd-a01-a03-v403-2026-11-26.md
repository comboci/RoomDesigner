- Baseline: main@6b71755d96ef2f7e9cae78cb5a60d01db944d4cf (V402-R)
- Severity: P1; source fixes, runtime pending. Both missions remain partially open.

## RD-A01 — startup recovery
V402-R only gated the valid-local path; absent-local recovery ran asynchronously after the initial render. Render can normalize devices and schedule autosave, causing recovery to abort or the fresh drawing to overwrite the mirror. V403 waits for recovery using the captured snapshot before first editor render; a failed read from an open DB blocks the gate. An unrecoverable mirror is preserved until user-requested raw export and explicit acknowledgment of external retention and fresh continuation. If the DB cannot open, legacy local-only mode remains available with a warning. Valid local authority is unchanged.

## RD-A03 — local migration backup
The original rd_preserved_migration_v325 archive is immutable. Distinct snapshots are appended as rd_preserved_migration_v325:N; prior archives are excluded from new payloads. Byte-identical key/value sets reuse an existing archive. Invalid archive or quota failure stops migration before new data writes. The export retains legacy local/preservedMirror fields and adds every raw archive, without deleting archives or removing the export button.

## Remaining
- OPEN-CROSS-STORE: no single transactional authority or cross-store atomicity. No schema migration or auto-merge.
- Earlier startup migrations and pending journal handling still precede the protection gate; fixed legacy IDB migration archives, invalid-local handling and restore workflow require additional work.
- Archive growth can exhaust LocalStorage quota; retention/pruning and external durable archive workflow need user-controlled design. No automatic pruning.
- Five new regression scenarios plus existing contracts revised; NOT_RUN under POLICY. No build, runtime/browser/device verification. Accept only on isolated data/browser after owner authorizes execution.
